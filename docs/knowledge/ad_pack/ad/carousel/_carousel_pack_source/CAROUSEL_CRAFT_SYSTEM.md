# Carousel Craft System

## 1. What a carousel actually is

A carousel is not merely a sequence of designed panels. In the strongest examples in the corpus, it behaves as a **progressive information experience** with three simultaneous jobs:

1. **Acquire attention** — the cover must earn the first swipe.
2. **Sustain progression** — every subsequent slide must justify its existence and maintain forward motion.
3. **Create a residue** — the viewer should leave with a memorable idea, useful artifact, changed perception, emotional impression, or next action.

The best general mental model is:

> **Cover promise → validation → progression → payoff → residue/action**

Not every carousel needs every stage explicitly, but weak carousels usually fail because one of these stages is missing.

---

## 2. The central law: local completeness + global incompleteness

**CORE**

Each slide should usually:
- communicate one dominant idea;
- make sense quickly;
- have a clear reading order;
- feel worth seeing on its own.

But the carousel as a whole should still contain:
- unresolved questions;
- increasing specificity;
- an incomplete transformation;
- an unfolding example;
- escalating stakes;
- a promised payoff;
- or aesthetic/narrative momentum.

This resolves the tension between two source ideas:
- “Every slide should work as a screenshot on its own.”
- “Every slide should make the next slide necessary.”

A useful design test:

> If this slide were shared alone, would it still make sense? If the carousel stopped here, would the viewer still prefer one more slide?

Both should usually be yes.

---

## 3. One dominant job per slide

**CORE**

A slide can contain several elements, but it should have one dominant communicative job.

Common slide jobs:
- stop;
- orient;
- validate;
- state the problem;
- raise the stakes;
- reframe;
- explain a mechanism;
- show an example;
- compare alternatives;
- demonstrate proof;
- provide a step;
- summarize;
- make a quotable point;
- transition;
- reveal;
- invite action.

A slide becomes weak when multiple jobs compete for equal priority.

Bad pattern:
- headline + paragraph + diagram + quote + screenshot + CTA + decorative elements all fighting for attention.

Better:
- one dominant message;
- secondary evidence or support;
- everything else subordinate.

---

## 4. The cover is a separate design problem

**CORE**

The cover is not “slide 1 of the explanation.” It is the acquisition layer.

Strong covers in the corpus tend to do at least two of the following:
- communicate the topic immediately;
- create a desirable outcome;
- create tension or contradiction;
- signal specificity;
- signal useful quantity;
- imply a framework/system;
- create visual intrigue;
- create identity relevance;
- create urgency or a mistake to avoid.

The cover should generally not try to explain the whole post.

A practical constraint from the corpus:
- the core premise should remain understandable at small feed size;
- typography should survive thumbnail reduction;
- the visual should not require close reading to work.

See `HOOKS_COVERS_AND_SWIPE.md`.

---

## 5. Slide 2 is disproportionately important

**STRONG INFERENCE**

Several strong educational examples use slide 2 to confirm that the cover was not empty bait.

Slide 2 commonly performs one of these jobs:
- restate the promise with more specificity;
- establish the problem;
- create stakes;
- show the result or transformation;
- present the framework map;
- demonstrate proof;
- begin the story immediately.

A weak slide 2 often causes a “promise collapse”: the viewer swiped because the cover was interesting, but discovers generic filler.

Useful rule:

> Cover earns curiosity. Slide 2 earns trust.

---

## 6. Sequence must create progression, not repetition

**CORE**

A carousel is not improved by adding more slides that restate the same idea.

Strong sequences change state. Examples:
- vague → specific;
- problem → cause → solution;
- old belief → contradiction → new belief;
- claim → mechanism → evidence → application;
- setup → escalation → reveal → consequence;
- overview → components → examples → synthesis;
- before → after → explanation;
- collection → comparison → selection rule.

A slide should be removable only if it is redundant.

Useful deletion test:

> If removing a slide does not damage meaning, rhythm, proof, or payoff, remove it.

This is more precise than “every slide must be essential to the story,” because some useful carousels are modular lists rather than stories.

---

## 7. Compression is a design skill, not just shorter copy

**CORE**

Strong educational carousels compress information through:
- hierarchy;
- chunking;
- diagrams;
- labels;
- examples;
- contrast;
- visual grouping;
- named components;
- progressive disclosure.

Weak compression merely deletes nuance until the content becomes generic.

The goal is not “few words.” The goal is:

> **High information value per unit of attention.**

A dense slide can work when:
- the reader expects reference value;
- hierarchy is extremely clear;
- the information is chunkable;
- the slide rewards saving.

A sparse slide can fail when it says almost nothing.

---

## 8. Saveability is not identical to density

**STRONG INFERENCE**

The corpus contains highly saveable slides in several forms:
- a framework diagram;
- a checklist;
- a named layout;
- a list of examples;
- a comparison;
- a concise quotable principle;
- a visual reference;
- a step-by-step technique.

Therefore “make one dense value slide” is too narrow.

A saveable slide usually has one of these properties:
- reference value;
- reuse value;
- memorability;
- quotability;
- decision support;
- implementation value.

---

## 9. Visual evidence is stronger than decorative imagery

**CORE**

The strongest educational examples use visuals as evidence or explanation:
- before/after;
- diagrams;
- screenshots;
- charts;
- real examples;
- product shots tied to the point;
- annotated comparisons;
- process photography.

Decorative imagery is still useful for mood, but it should not masquerade as explanation.

Generation rule:

> First ask what visual would prove, clarify, demonstrate, or embody the idea. Only then ask how to decorate the slide.

---

## 10. Rhythm matters across the sequence

**CORE**

Strong carousels rarely feel like ten identical posters.

Rhythm can change through:
- scale of typography;
- image vs text balance;
- background tone;
- diagram vs statement;
- dense vs sparse slides;
- full-bleed image vs framed image;
- question vs answer;
- list vs example;
- color inversion;
- visual zoom level;
- camera distance or subject scale.

But variation should occur inside a coherent system.

Useful distinction:
- **consistency** = same visual language;
- **repetition** = same composition over and over.

The system wants consistency without mechanical repetition.

---

## 11. Coherence comes from repeated invariants

**CORE**

Carousels remain coherent even when layouts change if they preserve enough invariants, such as:
- type family;
- accent color;
- margin system;
- image treatment;
- texture;
- border system;
- slide numbering;
- icon style;
- recurring motif;
- headline voice;
- framing device.

The AI should explicitly choose 3–6 invariants before designing individual slides.

Example:
- invariant: white textured paper background;
- invariant: black grotesk + editorial serif;
- invariant: orange accent;
- invariant: top micro-header;
- variable: image placement and headline composition.

This produces recognizable variety rather than random variety.

---

## 12. The carousel can be content-first, image-first, or experience-first

**CORE**

The corpus contains three fundamentally different production modes.

### A. Content-first
The idea exists first; design clarifies it.
Examples: frameworks, business essays, typography lessons, marketing explanations.

### B. Image-first
The visual material is the content.
Examples: travel photography, automotive detail photography, product art direction.

The task is sequencing, curation, contrast, and mood—not forcing text onto every image.

### C. Experience-first
The carousel is designed around the sensation of progressing through it.
Examples: visual storytelling sequences, before/after transformations, rhythmic editorial systems.

An AI generator must identify the correct production mode before it starts writing slides.

---

## 13. Text is not mandatory on every slide

**CORE**

Several effective visual carousels use little or no text after the cover.

For image-first carousels, forcing a lesson onto every frame reduces quality.

Use text when it:
- changes interpretation;
- guides attention;
- establishes progression;
- adds context;
- creates a narrative beat;
- explains a process;
- makes a useful distinction.

Do not use text merely because “a carousel needs copy.”

---

## 14. Aesthetic carousels need curation logic

**STRONG INFERENCE**

Photo and art-direction carousels still need sequence design.

Useful sequence variables:
- wide → medium → detail;
- environment → object → texture;
- calm → intense → calm;
- color echo;
- shape echo;
- human presence vs absence;
- exterior → interior;
- setup → lived moment → detail;
- repeated subject from different perspectives.

The viewer may not consciously identify the logic, but sequence coherence changes perceived quality.

---

## 15. Narrative carousels work through state changes

**CORE**

Story-based carousels become interesting when something changes.

Possible state changes:
- belief;
- knowledge;
- status;
- emotion;
- risk;
- identity;
- relationship;
- outcome;
- interpretation.

A useful rule extracted from the intentional-storytelling material:

> The event is not automatically the story. The shift is the story.

For generation, define before writing:
- before state;
- triggering event or tension;
- after state;
- lesson/meaning;
- why the audience should care.

---

## 16. CTA should be downstream of the value

**CORE**

The corpus uses several CTA types:
- comment keyword;
- save;
- share;
- follow;
- DM;
- link in bio;
- book a call;
- visit a business;
- read/watch a larger resource.

The strongest CTA is usually aligned with the content just consumed.

Examples of alignment:
- hook lesson → “comment HOOK for more hooks”;
- layout lesson → “comment LAYOUT for the full breakdown”;
- local detailing pain → visit/book detailing;
- portfolio/storytelling example → inquire about visual storytelling.

Weak CTA:
- unrelated offer appended to a random topic.

Generation rule:

> The CTA should feel like the next logical step, not a tax charged at the end.

---

## 17. A carousel can deliberately have no hard CTA

**OPTIONAL / STYLE**

Some thought-leadership or aesthetic posts end with a strong concluding line instead of a conversion ask.

This can be appropriate when the goal is:
- identity;
- brand impression;
- thought leadership;
- portfolio quality;
- shareability;
- emotional resonance.

Do not force lead-generation mechanics into every carousel.

---

## 18. Good carousels control reading order

**CORE**

The viewer should know what to inspect first, second, and third without effort.

Reading order is controlled by:
- size;
- weight;
- contrast;
- position;
- proximity;
- whitespace;
- arrows/lines;
- image gaze/direction;
- containers;
- numbered steps;
- color emphasis.

A visually attractive slide can still fail if attention is distributed evenly across competing elements.

---

## 19. Good design reduces search cost

**STRONG INFERENCE**

The repeated function of hierarchy, grids, spacing, and clear slide roles can be summarized as reducing **search cost**.

The user should not have to ask:
- where do I start?
- what is the main point?
- what belongs together?
- what changed?
- where do I go next?

The slide should answer those visually.

---

## 20. Carousel generation should optimize for a sequence, not independent posters

**CORE**

A common AI failure mode is generating ten individually attractive panels with no sequence logic.

The planner must create the entire **slide-role graph** before rendering any slide.

Minimum plan per slide:
- role;
- core idea;
- relationship to prior slide;
- reason to continue;
- visual function;
- dominant element;
- density level;
- continuity device;
- evidence/asset requirement;
- whether it must work independently.

Only after this plan passes QC should visual generation begin.

---

## 21. The strongest general production loop

1. Define the desired viewer change.
2. Define the single-sentence thesis.
3. Choose content mode: content-first, image-first, or experience-first.
4. Choose an archetype.
5. Write the cover promise.
6. Design slide 2 to validate the promise.
7. Build the sequence as changing states, not repeated points.
8. Decide which slide(s) should be especially saveable/shareable.
9. Assign a visual function to every slide.
10. Choose visual invariants.
11. Introduce controlled rhythm variation.
12. Add proof/examples where claims need support.
13. Choose a CTA only if it follows naturally.
14. Run sequence QC.
15. Run thumbnail/hierarchy QC.
16. Render.
17. Run final visual + copy QC.

---

## 22. What should NOT become universal rules

The corpus contains advice that is useful only as a heuristic or style choice.

Do **not** encode these as hard laws:
- “Never center-align text.”
- “Every carousel must use the newest exact pixel dimensions.”
- “Every slide must work completely independently.”
- “Every carousel needs a CTA.”
- “Every cover must have fewer than eight words.”
- “Carousels always outperform reels.”
- “Every carousel needs one screenshot-worthy slide.”
- “Minimal is always better.”
- “Every slide needs a different layout.”

Instead encode the underlying mechanisms:
- clear reading order;
- feed-size legibility;
- relevance;
- continuation;
- coherence;
- progression;
- appropriate density;
- visual hierarchy;
- audience value.
